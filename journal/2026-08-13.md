## What I learned
- k=6 was cheap because both halves of the MITM are the same
  triples dict — no new memory, no new build step. k=7 looked
  walled off (a 13.6M-entry Python dict is ~1.5-2GB; half-split
  alternatives need C(68,5)=10.4M dicts or ~10^8 on-the-fly loops
  per frame) until the representation shift: dicts cost ~100B per
  entry, a sorted numpy array costs 12B and searchsorted replaces
  hashing. The 37-bit masks (40 components) were the key check.
  Same trick gives k=8 (quads x quads over the same array, L=323/
  322) essentially free; k=9 needs the C(136,5)=57M quints array
  (~750MB — borderline, only if the program gets that far).
  palmitm.py's nonets-style joins remain capped/incomplete by
  design (fixed 5A x 4B split), fine for existence, not censuses.
